# 行业与企业发展潜力评估

本 Skill 的核心是研究并构建一套合理、可比较、能够实际评价的维度体系。以行业、子赛道或企业为目标，研究目标与历史、现实参照的发展和经营机制，形成共同的分层维度与评分标尺，再逐项评价和汇总。模型据此解释发展位置、竞争力与投资吸引力，Excel 承载其证据和计算。用户另有明确决策用途时，按该用途重新设计维度。

**前期重点是信息搜索、原文研读、研究加工、维度提取与赋分。实际建模以可追溯的公开材料支撑为基础，先广泛理解行业和参照，再建立评价体系。** 模型知识用于提出问题、解释材料和推导判断；实际对象的事实与评分依据须落实到材料。

本 Skill 自行完成信息搜索与研究、模型结构、指标、公式、权重、锚点、计算审计和工作簿；可复用已有研究及其来源，按本题补齐覆盖和时效。

本 Skill 是**特殊能力的独立行研 Skill**，不属于 `hehe-industry-researcher` 与13个专项组成的行业研究技能包，也不以其中任何 Skill 为安装、调用或交付条件。它以独立 Skill、独立仓库交付；其他研究结果只作为可选输入。

交付物、保存、信息缺口与验收规则见[`references/行业建模交付模板.md`](references/行业建模交付模板.md)；HTML 阅读版的生成与检查见[`references/HTML报告交付规范.md`](references/HTML报告交付规范.md)。

进入前期研究时读取[信息搜索与研究加工](references/信息搜索与研究加工.md)，按 Step 3A 执行；检索、研读和评分共用同一份材料索引。

## 工作流总览

目标与参照的多轮搜索 → 研读并解释发展条件 → 提取评价维度 → 补搜并设计标尺与权重 → 逐项评分与比较 → 检查关键假设 → 交付 Markdown、HTML 阅读版与可调 Excel。

直接评分、横向对比和组合加权共用这条流程。研究、取数和试评可以往返推进，试评中发现定义不合适就调整模型。

---

## Step 1：明确对象与用途

沿用用户已经给出的对象、用途、地域、时期和比较层级。信息不明且会改变模型时，集中问一次；已有材料、优先信源和排除范围一并记录。用户要求直接研究时，说明采用的范围后开始。

默认用途是评价行业发展潜力、竞争力或投资吸引力。研究具体企业时，明确是评价经营竞争力、进入机会还是特定价格下的投资回报。

明确主要评价当前实力还是未来潜力，并写出观察时点和判断期限。当前实力看已形成的能力与结果；未来潜力看需求空间、改善条件及实现可能性，据此选择指标和权重。共用研究材料形成主模型，未来改善另作情景比较。

---

## Step 2：确定比较对象与建模模式

先列目标、理想模型、历史高峰参照候选，以及有助于定位的当前同类或替代对象；经搜索核实后确定参照的时期和选择理由。行业比较行业，企业比较企业；跨时间比较使用含义一致的标准，金额、渗透率等数据统一口径。

| 模式 | 要回答的问题 | 做法 |
|---|---|---|
| **直接评分** | 一个行业或企业处于什么水平，发展机会在哪里？ | 与理想模型、历史高峰和适用的当前参照逐维度比较 |
| **横向对比** | 同类赛道或企业中，哪些更值得关注？ | 使用共同维度、标尺和权重，解释各自优势与制约 |
| **组合加权** | 各子赛道怎样共同构成母赛道的表现？ | 先评子赛道，再按规模或与用途对应的权重汇总，与母赛道判断核对 |

同一项目可以同时使用上述模式；整体与子赛道的衔接见文末多层级分析协议。

历史参照先简要比较候选的需求与采用过程、商业模式、资本及配套条件，说明为何选择这个对象和时期、哪些条件可以迁移。必要时加入停滞或失败案例，检验成功条件是否充分；候选取舍留在底稿，报告呈现最终选择理由。

## Step 3A：多轮搜索、研读与研究加工

研究目标和历史参照各自为什么兴起、加速、成熟或受阻：需求和痛点是什么，政策与经济社会环境怎样影响采用，技术与成本解决了什么，产业配套、竞争和盈利如何变化。历史参照要研究其高峰时期的成功条件及当时仍存在的短板。

按[信息搜索与研究加工](references/信息搜索与研究加工.md)执行以下过程：

1. **展开搜索**：沿用已有材料和索引，列目标、子赛道、历史及当前参照的待查问题。用中英文、别名、上下位品类、代表企业、事件与时期组合查询，主动扩展来源和对象。
2. **逐轮深入**：先广搜行业全貌，再深查发展驱动、痛点、成功与失败机制；提取候选维度后，针对各对象的评分事实、标尺和矛盾继续补搜。每轮新发现用于调整下一轮问题。
3. **多渠道取原文**：按问题读取统计、政策、企业披露、行业研究、技术论文、客户或用户材料。关键原文、表格和必要摘录留存并入索引；资料审核可用时调用 `baojie`，否则自行核对来源、时期、口径和冲突。
4. **从材料形成判断**：提炼`事实与来源｜解释的发展条件｜目标与参照的差异｜候选维度及选择理由｜待补问题`。用户提供的材料与公开检索一起使用，理想条件从发展机制和案例研究中归纳。

前期材料要覆盖主要发展条件和各比较对象，并能说明所选维度为什么重要。评分时继续补齐逐项依据；将检索进展和实质缺口保留在同一份研究底稿中。

## Step 3B：从发展条件中选择维度

先归纳一级维度，再拆成能说明强弱的指标。名称使用读者熟悉的行业语言，如“市场需求”“政策与监管”“技术成熟度”“竞争壁垒”“盈利潜力”。每项说明：为什么影响发展、比较什么、怎样判断好坏。

沿用八栏输入地图，把研究转成候选指标：

| 栏位 | 研究与选维度的方向 |
|---|---|
| ① 对象边界与口径 | 产品、业务、地域、时期和统计范围 |
| ② 子赛道或业务结构 | 细分对象、规模占比、共同指标与各自特点 |
| ③ 需求与发展驱动力 | 市场空间、需求强度、用户痛点、经济环境、社会习惯及采用变化 |
| ④ 供给与发展条件 | 技术成熟度、成本、人才、基础设施、供应链及渠道 |
| ⑤ 竞争与经营能力 | 竞争格局、进入壁垒、差异化、商业模式、盈利与资金需求 |
| ⑥ 政策、法律与发展障碍 | 政策支持、监管要求、知识产权、替代威胁及未解决的痛点 |
| ⑦ 指标与评价依据 | 可取的统计数据、可观察事实、合理代理，以及可解释的评分办法 |
| ⑧ 理想状态与参照 | 发展所需条件、历史成功案例及当前可比对象 |

一级维度按本题的重要因素归并。例如，政策、经济、社会、技术、法律可以帮助发现条件；驱动力和痛点可以帮助找到促进或制约发展的关键因素。最终维度取决于研究结果，名称和层级应让读者看懂。

行业特点可从以下变量池继续细化：

| 行业类型 | 常见核心变量 |
|---|---|
| 消费品/硬件 | 需求、品牌、渠道、复购、价格带、毛利、供应链 |
| 软件/SaaS | ARR、留存、NDR、CAC、LTV、毛利率 |
| 平台/互联网 | 网络效应、活跃用户、变现率、双边供需、流量成本 |
| 制造业/供应链 | 产能、良率、成本、客户认证、资本开支周期 |
| 医疗/生命科学 | 临床证据、审批、医院准入、医保支付、耗材复购 |
| 金融/保险 | 风险定价、资金成本、渠道、风控能力 |
| 能源/基础设施 | 政策、资本开支、利用小时、回报周期、并网资源 |
| 教育/内容服务 | 学习效果、内容/师资、获客、续费、合规 |
| B端项目制 | 客户关系、交付能力、回款周期、招投标、项目毛利 |
| 政策强监管 | 政策方向、准入门槛、执行情况、监管稳定性 |

企业模型同时研究团队、产品技术、客户与渠道、商业化、资金和组织能力。初创企业可根据团队经历、产品表现、客户验证和融资条件评价；成熟企业再结合财务和市场地位。

## Step 4：建立可实际使用的评分标准与权重

模型设计表写清：`一级维度｜指标｜为什么选｜观察什么｜评分标准｜权重｜权重理由`。一级维度回答主要判断问题，指标解释具体差异；仅在确有帮助时继续拆子指标。

**全模型统一使用 0—100 分，高分代表更有利。** 需求、技术、盈利等按表现由弱到强赋分；风险项按风险由高到低赋分。竞争集中度、进入壁垒等先结合评价对象确定方向： 在位企业的保护条件可能也是新进入者的障碍。

### 评分方法

- **定量指标**：用原始值、分档或连续公式换算为百分制。说明阈值为何代表本题的好坏程度。
- **定性指标**：依据具体事实作分析师判断，写清所处档位和给分理由。政策、需求、技术、生态等都可以这样评价。
- **混合指标**：数据与定性事实共同支持判断；必要时给子指标权重并汇总。

定性赋分示例——“政策支持”的可观察档位：

| 示例分值 | 对应表现 |
|---|---|
| 0 | 核心业务被禁止，或实际执行使其无法开展 |
| 25 | 限制较多、执行不稳定，明显增加经营成本 |
| 50 | 正常准入，政策影响总体中性 |
| 75 | 有明确支持措施，已有部分落实 |
| 100 | 支持稳定、广泛落实，对发展有实质促进 |

项目中据行业情况调整档位；中间分数解释介于两档的具体原因。**事实支持判断，判断形成分数。缺少精确统计值时，仍可用可靠事实完成定性评价。** 评分理由与原始资料分别记录，读者能看出哪部分是事实、哪部分是分析判断。

### 权重与试评

重要定性指标写清相邻档位的可观察差别，例如从“已有试点”到“稳定复购”需要看到什么事实；用目标与参照各试评一次，检查同样表现是否得到同样分数。中间分据事实强弱解释，争议较大时给出合理区间供敏感性分析。

一级维度权重合计100%，每个维度内的指标权重合计100%；全局指标权重＝两者相乘。权重理由说明因素对本次用途的影响程度、当前瓶颈和对象差异。研究因素重叠时合并或分配权重，避免同一收益或风险重复计入。

先对目标与参照的代表指标试评，检验同一标准能否解释它们的差异；标尺阈值结合研究中的实际分布、历史表现或有依据的条件差异制定。缺少评分依据时定向补搜。遇到抽象难懂、证据要求不切实际或评分没有区分度的指标，调整定义、观察办法或分档，再完成全表。

模型方案随研究结果展示。用户已经要求完成分析时，连续完成评分、比较和工作簿；用户明确要求先审方案时，才在方案处停下。

维度得分＝Σ（指标得分×维度内权重）；综合得分＝Σ（维度得分×维度权重）。权重与评分都是用户可调参数，Excel引用对应单元格计算。

## Step 4.5：构建理想模型，评价历史参照与目标

| 对象 | 需要研究和呈现的内容 |
|---|---|
| **理想模型** | 逐指标描述满分对应的发展条件，解释这些条件为什么有利、能否共同成立；据此给出本模型的100分标准 |
| **历史高峰参照** | 选择可类比行业或企业的明确时期，说明当时需求、技术、成本、生态、政策和商业化怎样共同促成成功，以及为什么适合本题 |
| **当前可比对象** | 根据需要选同类、成熟市场或替代对象，帮助判断目标今天处于什么位置 |
| **目标对象** | 按同一标准评价现状，解释与理想模型、历史高峰和当前参照的差距 |

理想模型要写出具体条件及其理由。对互相牵制的因素，说明合理平衡状态如何对应高分，例如增长与盈利、开放生态与利润留存。

历史参照按选定时期的状态评分，并解释时代环境差异。跨时代采用共同经济含义的指标，例如“可负担性”可用价格相对收入，“技术成熟度”可用当时核心需求的满足程度。历史高峰也有短板，其得分由逐项评价得出。

每个对象逐项填写：`事实或原始值｜来源｜适用档位｜得分｜评分理由`。汇总后呈现分维度与总体差距，指出哪些条件已经具备、哪些可以补齐、哪些需要环境变化。需要评级时，根据本题标尺解释分值区间。

对关键差距计算其对总分的贡献：`全局指标权重×（参照分－目标分）`；按维度加总定位主要落后与优势。改善优先级再结合可控程度、投入、时间和前置条件判断。对重要改善路径，用同一标尺列出“发生什么变化→哪些指标达到什么水平→总分变化”，保留基准权重，将改善情景与当前评分并列。

## Step 5：整理评分依据与资料来源

资料收集贯穿研究和赋分。保留来源名称、日期、原文链接或用户材料位置，并标记核实数据、二手数据、估算数据、数据缺口或待人工确认。估算写出输入与推算办法；定性评分写出事实与推理。

优先用官方统计、政策原文、企业披露、可信研究和可核对案例。用户材料与其他研究结果按原有对象、时期和样本范围使用；案例频次与行业总体比例分别处理。

证据充分程度在评分依据旁简要说明，评价分反映对象表现。只有缺口会影响结论或下一步时，才展开说明。

## Step 6：制作可阅读、可调节的 Excel

交付工作簿时读取[行业建模交付模板](references/行业建模交付模板.md)。首页先呈现维度权重、目标与参照的分维度得分、综合位置及关键差距；各表说明用途和可编辑位置。

权重、目标和参照评分均可调整，维度得分、总分和分差通过公式联动。全部采用0—100分，权重以百分比显示。保留评分理由、来源与理想条件，读者能顺着结果找到依据。

可用随包 `scripts/build_scoring_workbook.py` 和 `examples/model-input.example.json` 制作，也可用其他表格工具。随包脚本的字段与五张基本表见交付模板；组合加权、复杂计算和敏感性按需要加表。

## Step 7：检查模型是否支持判断

先检查维度是否覆盖主要发展条件，评分理由能否解释对象间的差异，再核对计算和结论。

- **缺口处理**：继续补查事实；精确数据缺少时，尝试事实分档、合适代理或有依据的区间。指标本身难以操作时修订定义。确实无法判断的项留空，保留已完成比较，并说明这项缺口可能改变什么结论。
- **结论稳定性**：改变关键权重、争议评分或估算参数，记录总分、排序和判断如何变化；选择有代表性的替代设定比较。存在翻转时说明触发条件，稳定时说明哪些优势持续成立。
- **硬约束**：业务合法性、必要安全条件或关键技术可行性等单列，说明是否满足及如何解决；它们与总分共同影响判断。
- **计算检查**：核对权重、评分尺度、公式引用、组合汇总及报告数字；实际打开重算，并试改一个权重和一个分数，确认相关结果联动。

使用随包脚本时执行 `python scripts/validate_scoring_workbook.py --workbook [工作簿路径] --contract [输入.json]`。生成基准版时核对输入与工作簿；用户调参后核对公式及结果，并更新受影响的解释。

## Step 8：交付分析结论

按[行业建模交付模板](references/行业建模交付模板.md)交付 Markdown 主报告、同内容 HTML 阅读版和 Excel。Markdown 定稿后，依照[HTML报告交付规范](references/HTML报告交付规范.md)生成 HTML，不另行改写结论或删减正文。正文以分析结果与逻辑为主：先回答目标处于什么位置、强弱在哪里、应重点关注哪些方向，再逐维度解释目标与参照的核心差距、成因及对发展和经营的影响。维度、权重与得分概览帮助定位，详细赋分依据由报告附录和 Excel 承接。

行业模型说明发展潜力及制约；子赛道模型解释关注优先级和各自条件；企业模型解释竞争位置、追赶机会和所需资源。投资潜力判断结合回报条件与风险，特定标的再考虑进入价格。

关键事实与来源随判断出现；按交付模板检查解读是否充分，并删减无助于事实、推理或判断的防御性和重复文字。

## 多层级分析协议

同时评价母赛道和子赛道时，共用核心维度、标尺与权重，先评子赛道，再按同口径规模占比或适用的组合权重汇总：

`母赛道各指标得分＝Σ（子赛道该指标得分×子赛道权重）÷Σ子赛道权重`

评价当前结构时使用同期规模占比；评价未来结构时使用注明时期和依据的情景占比。子赛道机会排序直接比较同口径评分，规模小也可能值得优先关注；按资源配置等其他用途组合时，注明权重含义和结果用途。工作簿显示权重合计，调参时归一化计算，基准版本保存为100%。

共同模型下，汇总总分与子赛道总分的加权平均一致。另做母赛道整体评价时，比较两者差距，解释细分覆盖、结构变化、协同或规模效应。子赛道专有指标可作补充分析，单独说明与共同模型的关系。

如果先做母赛道，完成细分后再核对。不同模型的权重或标准发生变化时，先对齐后比较。

## 输入与续作

用户提供已有模型时，先识别它有效的维度、评分理由和使用方式，再修正口径、公式或缺失能力。后续增加赛道或企业时，沿用共同标尺；研究发现需要调整标尺时，同步重评原对象。

用户只要方法或模板时交付设计说明与参数表；要求实际分析时完成对象研究、赋分和比较。
